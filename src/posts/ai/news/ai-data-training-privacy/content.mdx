9월 초, Mistral의 도움말 문서 하나가 Hacker News에 올라오면서 개발자들 사이에서 꽤 오래 회자됐습니다. 내용은 단순했습니다. **Vibe(구 Le Chat) 무료·Pro 사용자는 기본적으로 학습 대상에 포함되어 있고, 원하면 직접 끌 수 있다**는 것입니다. 반면 Enterprise 고객은 기본적으로 학습에서 제외됩니다.

새로운 이야기는 아닙니다. 대부분의 AI 서비스가 "개인용은 기본 학습, 기업용은 기본 제외"라는 비슷한 구조를 갖고 있습니다. 하지만 **"유료니까 당연히 학습 안 하겠지"라는 가정이 틀릴 수 있다**는 점을 다시 확인시켜 준 사례라서, 이번 기회에 주요 서비스의 정책을 한 번에 정리해 봤습니다.

> ⚠️ 이 글의 모든 내용은 **2026년 9월 기준** 각 사 공식 도움말·정책 페이지를 확인한 것입니다. 데이터 정책은 자주 바뀌므로, 실제 적용 전에는 반드시 원문을 다시 확인하세요.

## 🌀 Mistral: "유료 = 학습 제외"가 아니었다

Mistral은 2026년 5월 챗봇 Le Chat의 이름을 **Mistral Vibe**로 바꿨습니다. 공식 도움말 기준으로 Vibe의 학습 정책은 다음과 같습니다.

- **Vibe Free / Pro**: 기본값이 학습 **허용** 상태입니다. 사용자가 언제든 끌 수 있습니다.
- **Vibe Team**: 관리자가 조직 전체의 학습 사용을 끌 수 있습니다.
- **Vibe Enterprise**: 기본적으로 학습에서 **제외**됩니다.
- **Mistral Studio(API)**: 고객이 언제든 옵트아웃할 수 있으며, 관리 패널의 Privacy 메뉴에 있는 "Anonymous improvement data" 토글로 제어합니다.

여기서 개발자가 가장 놓치기 쉬운 부분은 **Vibe 토글과 API 토글이 서로 별개**라는 점입니다. Mistral 도움말은 한쪽을 끈다고 다른 쪽까지 꺼지지 않는다고 분명히 적고 있습니다. 채팅 앱에서 옵트아웃했다고 안심하고 API 키로 사내 도구를 붙였다면, 두 설정을 각각 확인해야 합니다.

**옵트아웃 방법 (Vibe)**

- 웹: Admin panel → Manage의 Vibe → Privacy 섹션에서 "Allow your interactions to be used to train our models" 끄기
- 모바일: Settings → Data & Account Controls → "Enable data sharing" 해제

개인적으로는 이 사례가 정책 자체보다 **"기본값"의 힘**을 보여준다고 생각합니다. 옵트아웃 기능이 있어도 대부분의 사용자는 설정 화면을 열어보지 않습니다. 기본값이 곧 실제 정책입니다.

## 🤖 OpenAI: 개인은 옵트아웃, API는 2023년부터 기본 제외

- **ChatGPT Free / Plus / Pro**(개인 워크스페이스): 데이터 공유가 기본으로 켜져 있습니다. Settings → Data controls → **"Improve the model for everyone"**을 끄면 이후 새 대화는 학습에 쓰이지 않습니다. Privacy Portal에서 요청하는 방법도 있습니다.
- **ChatGPT Business / Enterprise / Edu, API**: 기본적으로 입력·출력을 학습에 사용하지 않습니다.
- **API**: 2023년 3월 1일부터 명시적으로 옵트인하지 않는 한 학습에 쓰이지 않습니다. 다만 악용 모니터링 로그는 기본 최대 30일 보관되며, 승인받은 고객은 **Zero Data Retention(ZDR)** 또는 Modified Abuse Monitoring을 조직·프로젝트 단위로 선택할 수 있습니다.
- **임시 채팅(Temporary Chat)**: 기록에 남지 않고 모델 개선에 쓰이지 않으며, 안전 목적으로 최대 30일 보관 후 삭제됩니다.

주의할 점은 **피드백**입니다. 옵트아웃했더라도 👍/👎를 누르면 해당 대화 전체가 학습에 쓰일 수 있다고 안내되어 있습니다.

---

## 🧠 Anthropic: 소비자는 "선택", 상업용은 기본 제외

- **Claude Free / Pro / Max**(해당 계정으로 쓰는 Claude Code 포함): 개인정보 설정에서 모델 개선 허용 여부를 **사용자가 선택**합니다. 허용하면 새로 시작하거나 재개한 대화·코딩 세션이 학습에 쓰일 수 있고, 비식별화된 형태로 최대 5년까지 보관될 수 있습니다. 허용하지 않으면 기존 보관 정책이 적용됩니다.
- **시크릿(Incognito) 채팅**: 모델 개선 설정을 켜 두었더라도 학습에 쓰이지 않습니다.
- **상업용(Claude for Work, API, Claude Gov 등)**: Anthropic은 기본적으로 상업용 제품의 입력·출력을 학습에 쓰지 않는다고 밝히고 있습니다. 예외는 사용자가 명시적으로 피드백을 보내거나 옵트인한 경우입니다.
- **API ZDR**: 영업팀을 통해 조직 단위로 ZDR을 신청할 수 있습니다. 다만 Batch API, Files API, 코드 실행처럼 상태를 저장해야 하는 기능은 ZDR 대상이 아니고, 일부 모델은 30일 보관이 필수라 ZDR로 쓸 수 없다는 점도 문서에 명시되어 있습니다.

공통적으로 **안전 정책 위반으로 플래그된 대화**는 설정과 무관하게 더 오래(최대 2년) 보관될 수 있습니다. 이런 예외는 대부분의 사업자에게 비슷하게 존재합니다.

## 🔷 Google: 앱·Workspace·API가 전부 다르다

Google은 같은 Gemini라도 어디서 쓰느냐에 따라 정책이 크게 달라집니다.

- **Gemini 앱(개인 계정)**: 성인 기준 **Keep Activity**가 기본으로 켜져 있고(자동 삭제 기본 18개월), 켜져 있는 동안 활동이 모델 개선에 활용됩니다. 일부 대화는 계정과 분리된 상태로 사람 검토자가 볼 수 있으며, 검토된 대화는 최대 3년 보관됩니다. 끄더라도 서비스 제공·안전을 위해 72시간은 보관됩니다.
- **Google Workspace의 Gemini**: 고객의 허락 없이 도메인 밖에서 생성형 AI 모델 학습이나 사람 검토에 쓰이지 않는다고 안내합니다.
- **Gemini API / AI Studio**: 무료(Unpaid) 사용분은 제품과 머신러닝 기술 개선에 활용되며 사람이 검토할 수 있습니다. 약관은 무료 서비스에 "민감하거나 기밀인 개인정보를 넣지 말라"고 직접 경고합니다(Gemini API 추가 서비스 약관). **유료(Paid) 사용분**은 개선에 쓰지 않고, 위반 탐지 목적의 로그만 제한적으로 보관합니다.

개발자 입장에서 특히 조심할 곳은 **AI Studio와 무료 API 키**입니다. 프로토타입 단계에서 실제 고객 데이터를 넣어 테스트하는 일이 흔한데, 이 경우 무료 약관이 적용됩니다.

## 🐙 GitHub Copilot: 2026년 4월부터 개인 플랜도 학습 대상

GitHub는 2026년 3월 공지를 통해 **4월 24일부터 Copilot Free·Pro·Pro+ 사용자의 상호작용 데이터**(입력, 출력, 코드 조각, 관련 컨텍스트 등)를 옵트아웃하지 않으면 모델 학습에 사용한다고 밝혔습니다.

- **옵트아웃**: 프로필 → Copilot settings → "Allow GitHub to use my data for AI model training"을 Disabled로 변경
- 이전에 관련 설정을 꺼 두었다면 그 선택이 유지됩니다.
- **Copilot Business / Enterprise**는 이번 변경의 영향을 받지 않고, 이 설정 자체가 노출되지 않습니다.
- 저장소에 **저장된(at rest)** 비공개 코드는 학습에 쓰지 않는다고 밝혔지만, Copilot 사용 중 처리되는 비공개 저장소 코드 조각은 상호작용 데이터로 포함될 수 있습니다.

개인 계정으로 회사 코드를 다루는 개발자라면 가장 먼저 확인해야 할 설정입니다.

## ✅ 개발자·회사 체크리스트

**개인 개발자**

- [ ] 사용하는 모든 AI 서비스의 학습 설정을 직접 열어 확인하기 (ChatGPT, Claude, Gemini, Vibe, Copilot)
- [ ] 채팅 앱과 API의 설정이 **분리되어 있는지** 확인하기 (Mistral처럼 토글이 따로인 경우)
- [ ] 민감한 작업은 임시 채팅·시크릿 채팅 사용하기
- [ ] 옵트아웃 상태에서도 👍/👎 피드백은 학습에 쓰일 수 있다는 점 기억하기
- [ ] 개인 Copilot 계정으로 회사 코드를 다룬다면 학습 설정 끄기

**절대 붙여넣지 말아야 할 것**

- [ ] API 키, 토큰, 비밀번호, `.env` 파일 내용
- [ ] 고객 개인정보, 운영 DB 덤프, 실제 로그 원본
- [ ] 계약서·가격 정책 등 공개되지 않은 사업 정보
- [ ] 옵트아웃했더라도 안전 검토·법적 보관 예외가 있으므로, **"학습 안 됨 = 저장 안 됨"이 아니라는 점** 기억하기

**회사·팀**

- [ ] 업무용 AI는 **기업 플랜(Business/Enterprise/Team)** 으로 통일하고, 개인 계정 사용 정책을 명문화하기
- [ ] API 연동은 유료 티어에서만 하고, 무료 키(예: AI Studio 무료 사용분)로 실데이터 테스트 금지
- [ ] 규제 데이터를 다룬다면 **ZDR** 또는 HIPAA 같은 별도 약정 여부를 영업팀과 확인하기
- [ ] ZDR을 적용해도 제외되는 기능(배치, 파일 저장, 코드 실행 등)이 있는지 문서로 점검하기
- [ ] 사전 커밋 훅이나 시크릿 스캐너로 프롬프트·코드에 비밀값이 섞이지 않게 막기
- [ ] 분기마다 각 사 정책 페이지를 다시 확인하는 담당자 지정하기

## 💡 마무리

정리하면 업계의 큰 틀은 비슷합니다. **개인용 서비스는 학습이 기본이거나 사용자 선택, 기업용·API는 기본 제외**입니다. 하지만 Mistral처럼 유료 개인 플랜도 학습 대상인 경우가 있고, GitHub Copilot처럼 정책이 중간에 바뀌기도 하며, Google처럼 같은 모델이라도 경로마다 규칙이 다릅니다.

결국 가장 확실한 방어는 두 가지입니다. **설정을 직접 확인하는 습관**, 그리고 **애초에 민감한 정보를 넣지 않는 습관**입니다. 오늘 한 번만 시간을 내서 쓰고 있는 AI 서비스의 설정 화면을 모두 열어 보시길 권합니다.
